Multi-target Phase 3 RDA 후보 검출 모드 추가

목적

range-Doppler-angle 후보를 DBSCAN에서 바로 1개로 접지 않고 tracker 입력까지 유지하는 replay 모드를 만들어, multi-target 분리 가능성을 검증했다.

수정 파일

  • tools/lab/stage_cache.py

변경 내용

  • Stage Cache ablation mode에 rda_candidates를 추가했다.
  • rda_candidates 모드에서는 angle_source=doppler_slice_rai로 두고 enable_dbscan=false로 재처리한다.
  • 이 모드는 live 기본 동작을 바꾸지 않고, 같은 raw에 대한 검증 모드로만 동작한다.

검증 명령 또는 확인 방법

python -c "from pathlib import Path; compile(Path('tools/lab/stage_cache.py').read_text(encoding='utf-8'), 'tools/lab/stage_cache.py', 'exec'); print('syntax ok')"
python -B -m tools.lab.stage_cache --session 20260508_193458 --mode rda_candidates --force
python -B -m tools.diagnostics.multitarget_stage_eval --session 20260508_193458 --mode rda_candidates --expected-max 2 --min-separation-m 0.65 --min-doppler-bins 7 --min-score-ratio 0.05 --jump-threshold-m 0.85

결과

  • 보고서: logs/diagnostics/multitarget_stage_eval_20260511_041433_20260508_193458__rda_candidates/report.html
  • display_two_or_more_rate: 0.78
  • dbscan_collapse_rate_on_multi_evidence: 0.0
  • tracker_collapse_rate_after_dbscan_multi: 0.2218
  • over_expected_max_rate: 0.02

남은 위험 또는 다음 후보

  • DBSCAN collapse는 사라졌지만, 5프레임에서 3개로 과분리되었다.
  • 다음 단계에서는 RDA 후보를 유지하되 object count estimate를 이용해 같은 사람 내부 산란점만 정리하는 merge/DBSCAN 정책이 필요하다.
