Multi-target Phase 1 Ablation Replay 모드 추가 및 검증

목적

기준 세션 20260508_193458에서 2명 교차/왕복 추적이 어느 처리 단계에서 무너지는지 같은 raw 데이터의 ablation replay로 분리했다.

수정 파일

  • tools/lab/stage_cache.py
  • tools/diagnostics/multitarget_stage_eval.py

변경 내용

  • Stage Cache ablation mode에 no_duplicate_suppression을 추가했다.
  • no_duplicate_suppression 모드에서는 duplicate_suppression_enabled=false로 재처리한다.
  • 진단 도구가 --mode로 <session>__<mode> 캐시를 읽을 수 있게 했다.

검증 명령 또는 확인 방법

python -c "from pathlib import Path; compile(Path('tools/diagnostics/multitarget_stage_eval.py').read_text(encoding='utf-8'), 'tools/diagnostics/multitarget_stage_eval.py', 'exec'); compile(Path('tools/lab/stage_cache.py').read_text(encoding='utf-8'), 'tools/lab/stage_cache.py', 'exec'); print('syntax ok')"

$modes = @('baseline','no_body_center','no_duplicate_suppression','no_dbscan','tracker_off','doppler_slice_angle')
foreach ($m in $modes) {
  python -B -m tools.lab.stage_cache --session 20260508_193458 --mode $m --force
  python -B -m tools.diagnostics.multitarget_stage_eval --session 20260508_193458 --mode $m --expected-max 2 --min-separation-m 0.65 --min-doppler-bins 5 --min-score-ratio 0.05 --jump-threshold-m 0.85
}

no_dbscan에서 2명 이상 표시 비율이 크게 올라가므로, 현재 기준 세션의 주요 병목은 duplicate suppression보다는 DBSCAN/cluster 병합 쪽으로 판단한다.

남은 위험 또는 다음 후보

  • no_dbscan은 2명 유지에는 유리하지만 3개 과분리 프레임이 일부 생긴다.
  • 다음 단계에서는 DBSCAN을 단순 제거하지 않고, range/doppler/angle 분리 근거로 예상 object count를 추정한 뒤 merge/cluster가 그 수를 과하게 줄이지 않도록 조정해야 한다.
