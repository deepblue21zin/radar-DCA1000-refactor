Stage Cache 중첩 replay 원본 raw 해석 보강

목적

replay session이 또 다른 replay session ID를 source로 기록한 경우에도 Stage Cache가 최종 원본 raw capture를 찾아가도록 보강한다.

수정 파일

  • tools/lab/stage_cache.py

변경 내용

  • summary.session_meta.source_capture와 summary.runtime_config.log_source_capture를 raw 후보로 추가했다.
  • source가 live/replay session ID처럼 보이면 해당 session의 summary.json을 읽어 실제 원본 raw capture를 추가 후보로 사용한다.

검증 명령 또는 확인 방법

python -B -c "from pathlib import Path; compile(Path('tools/lab/stage_cache.py').read_text(encoding='utf-8'), 'tools/lab/stage_cache.py', 'exec'); print('syntax ok')"
python -B -m tools.lab.stage_cache --session 20260511_054011 --force
python -B -m tools.diagnostics.multitarget_stage_eval --session 20260511_054011 --mode baseline --expected-max 2 --min-separation-m 0.65 --min-doppler-bins 7 --min-score-ratio 0.05 --jump-threshold-m 0.85

결과

20260511_054011 Stage Cache가 원본 logs/raw/20260508_193458로 정상 연결됐다. 진단 결과는 display 2명 이상 83.6%, DBSCAN collapse 0.0%, tracker collapse 7.73%, 3명 이상 과검출 21.2%로 확인됐다.

남은 위험 또는 다음 후보

DBSCAN collapse는 해결됐지만, 현재 live 설정은 2인 교차에서 3명 이상 과검출이 커졌다. 다음 단계는 object count limit 또는 tracker max object count를 2인 시나리오 기준으로 제한하는 실험이다.
