Multi-target Phase 0 관측/검증 리포트 도구 추가

목적

기준 세션 20260508_193458에서 2명 교차/왕복 상황의 실패 위치를 감으로 보지 않고, 후보 검출, DBSCAN, tracker, display 단계별 count collapse로 분리하기 위해 진단 도구를 추가했다.

수정 파일

  • tools/diagnostics/multitarget_stage_eval.py

변경 내용

  • Stage Cache의 frame_trace.jsonl, frames.jsonl을 읽어 multi-target 후보가 어느 단계에서 1개로 접히는지 집계한다.
  • multi_evidence_count, dbscan_collapse, tracker_collapse, display_collapse, track_jump 지표를 산출한다.
  • CSV, JSON, HTML 보고서를 logs/diagnostics/ 아래에 저장한다.
  • Phase 1 ablation 캐시 검증을 위해 --mode 인자를 추가했다.

검증 명령 또는 확인 방법

python -c "from pathlib import Path; compile(Path('tools/diagnostics/multitarget_stage_eval.py').read_text(encoding='utf-8'), 'tools/diagnostics/multitarget_stage_eval.py', 'exec'); print('syntax ok')"
python -B -m tools.diagnostics.multitarget_stage_eval --session 20260508_193458 --mode baseline --expected-max 2 --min-separation-m 0.65 --min-doppler-bins 5 --min-score-ratio 0.05 --jump-threshold-m 0.85

결과

  • 보고서: logs/diagnostics/multitarget_stage_eval_20260511_040436_20260508_193458/report.html
  • multi_evidence_rate: 0.76
  • dbscan_collapse_rate_on_multi_evidence: 0.6474
  • tracker_collapse_rate_after_dbscan_multi: 0.631
  • display_two_or_more_rate: 0.236
  • 주요 reason count: dbscan_collapse=123, tracker_collapse=53, rai_suspicious=49

남은 위험 또는 다음 후보

  • multi_evidence_count는 ground truth 라벨이 아니라 range/angle/doppler 분리 기반 휴리스틱이다.
  • 다음 단계에서는 같은 raw 세션을 ablation mode별로 재처리해 DBSCAN, duplicate suppression, tracker 중 어느 단계가 가장 큰 병목인지 비교해야 한다.
