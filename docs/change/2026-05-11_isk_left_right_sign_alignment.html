ISK raw 기준 좌우 부호 정렬

목적

사용자가 20260509_005846 세션을 실제로는 레이더 기준 왼쪽 대각선 왕복 운동이라고 확인했지만, 기존 Streamlit/Stage Cache 그래프와 raw-derived 3D point cloud가 오른쪽(+x)으로 보이는 문제가 있었다. raw ADC를 재처리한 dense 3D point cloud를 기준으로 좌우 convention을 다시 맞추고, 이후 Streamlit Stage Cache와 replay가 같은 부호를 쓰도록 정렬했다.

수정 파일

  • config/live_motion_tuning_isk.json
  • tools/lab/stage_cache.py

변경 내용

  • IWR6843ISK 튜닝의 angle_phase_sign을 1.0으로 설정했다.
  • Stage Cache raw 재처리 시 현재 튜닝의 angle_phase_sign을 우선 사용하도록 했다.
  • Stage Cache manifest.json에 angle_phase_sign과 angle_phase_sign_source를 기록하도록 했다.
  • 세션에 저장된 lateral_axis_sign은 그대로 보존해 과거 세션의 runtime intent를 유지한다.

검증 명령 또는 확인 방법

python -c "from pathlib import Path; files=['tools/lab/stage_cache.py','tools/diagnostics/raw_dense_pointcloud_3d.py','tools/diagnostics/raw_pointcloud_stage_visualizer.py','tools/runtime_core/virtual_array.py']; [compile(Path(f).read_text(encoding='utf-8'), f, 'exec') for f in files]; print('syntax ok')"
python -c "import json; json.load(open('config/live_motion_tuning_isk.json', encoding='utf-8')); print('json ok')"
python -B -m tools.lab.stage_cache --session 20260509_005846 --force
python -B -m tools.diagnostics.raw_dense_pointcloud_3d --session 20260509_005846 --frame 161 --top-k 600 --quantile 0.99

결과

  • 문법 검사: syntax ok
  • JSON 검사: json ok
  • Stage Cache 재생성: frame_count=250
  • Stage Cache runtime: angle_phase_sign=1.0, angle_phase_sign_source=current_tuning
  • Stage Cache 좌표 분포: confirmed tracks neg_ratio=1.0, lead confirmed neg_ratio=1.0
  • raw-derived 3D point cloud frame 161은 음수 x 방향에 형성되어 사용자가 말한 왼쪽 대각선 동작과 일치했다.

남은 위험 또는 다음 후보

  • 이미 저장된 과거 replay/report HTML은 자동으로 수정되지 않는다. 같은 raw를 새 설정으로 다시 replay해야 processed 결과가 바뀐다.
  • 좌우 부호는 정렬됐지만, 2명 이상 교차 추적의 ID 유지 문제는 별도 tracker/data association 개선이 필요하다.
  • 다른 세션도 같은 물리 방향 기준으로 맞는지는 코너 리플렉터 또는 명확한 좌/우 walking 세션으로 추가 확인하는 것이 좋다.
